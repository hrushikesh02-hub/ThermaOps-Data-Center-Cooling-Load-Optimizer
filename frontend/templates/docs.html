Request and result handling

POST and PUT require application/json. Unknown fields, invalid bounds, booleans in numeric fields, NaN and infinity are rejected. A stale revision or snapshot returns 409. A busy optimizer returns 429. All errors are JSON.

An optimization response uses HTTP 201 because it creates a saved run, including when status is infeasible. Only a non-null, feasible recommendation can be applied. Applying a run twice is idempotent. Changing limits invalidates earlier recommendations.

Limits: inlet 18–27°C; hotspot 20–35°C; reserve 0–5°C; optional point-prediction power cap 1–10,000 kW. Search bounds must stay within 18–27°C for setpoint/supply and 30–100% for fan/pump. Bounds and recommendations use 0.1-unit increments.

Thermal checks add one-sided validation residual allowances to predicted temperatures. This empirical margin has no guaranteed coverage under distribution shift. The server listens only on loopback and assumes a trusted local operator; it has no remote identity or facility control integration.
